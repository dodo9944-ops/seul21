# 백업 검증 및 복원 절차

## 1. 백업 검증 체크리스트

### 1-1. GitHub 백업 브랜치 확인
```bash
git ls-remote origin | grep backup-20260419
# 결과 예:
# <sha>  refs/heads/backup-20260419
# <sha>  refs/tags/backup-20260419-v1
```

### 1-2. GitHub Actions 아티팩트 확인
- https://github.com/dodo9944-ops/seul21/actions 접속
- 최신 "Backup to Google Drive" 워크플로 실행 결과 확인
- Artifacts 섹션에 `seul21_backup_20260419_<sha>.zip` 존재 확인

### 1-3. Google Drive 확인 (시크릿 설정 시)
- Drive → `00.공유폴더` → `세울21_백업` → `backup-20260419` 폴더 진입
- `seul21_backup_20260419_<sha>.zip` 존재 + `BACKUP_20260419.md` 함께 있는지

### 1-4. 로컬 ZIP 무결성 검증 (Windows PowerShell)
```powershell
Get-FileHash .\seul21_backup_20260419_*.zip -Algorithm SHA256
# 출력된 해시를 사용자 기록 보관
```

## 2. 부분 복원 (특정 파일만)

### 2-1. 특정 파일 1개 복원
```bash
git fetch origin backup-20260419
git checkout origin/backup-20260419 -- redevelopment/assets/data/mock-data.js
# 변경 확인 후 커밋
git status
git commit -m "restore: mock-data.js from backup-20260419"
git push origin master
```

### 2-2. 특정 폴더 전체 복원
```bash
git fetch origin backup-20260419
rm -rf redevelopment/downloads/
git checkout origin/backup-20260419 -- redevelopment/downloads/
git status
git commit -m "restore: downloads from backup-20260419"
git push origin master
```

## 3. 전체 복원 (위험 — 사용자 명시 승인 필수)

### 3-1. 안전한 방법 — 새 브랜치로 비교
```bash
git fetch origin
git checkout -b restore-test backup-20260419
# 로컬에서 테스트 후 현재 master에 필요 파일만 선별 복사
```

### 3-2. 강제 원복 (절대 단독 실행 금지)
**⚠ 이 명령은 반드시 사용자의 명시적 서면 승인 후 실행**
```bash
git checkout master
git reset --hard backup-20260419
git push origin master --force-with-lease
```

결과:
- master가 backup-20260419 시점으로 강제 되돌아감
- 이후 커밋은 모두 사라짐 (복구 어려움)
- Vercel이 자동 감지 → 재배포

## 4. ZIP 아카이브에서 복원

### 4-1. 새 저장소로 복원
```bash
# 1. ZIP 압축 해제
unzip seul21_backup_20260419_<sha>.zip -d seul21_restored/
cd seul21_restored/

# 2. 새 Git 저장소 초기화 (원격은 새 저장소)
git init
git add .
git commit -m "restore from backup-20260419"
git remote add origin https://github.com/사용자/새저장소.git
git push -u origin master

# 3. Vercel 새 프로젝트 연결
# 4. 환경변수 재설정 (06_로그인정보_템플릿.md 참조)
# 5. 도메인 재연결 (가비아 DNS)
```

### 4-2. 기존 저장소에 덮어쓰기
```bash
# 1. 기존 작업 안전 백업
git branch safety-$(date +%Y%m%d) master

# 2. 백업 ZIP 내용으로 덮어쓰기
cd /path/to/current/repo
rm -rf redevelopment/
unzip /path/to/backup.zip "redevelopment/*" -d .

# 3. 변경 확인 후 커밋
git status
git add redevelopment/
git commit -m "restore full redevelopment/ from backup-20260419"
git push origin master
```

## 5. 환경변수·시크릿 복원

ZIP 백업에는 포함되지 않음. 다음 위치에서 재설정:

### 5-1. Vercel 환경변수
1. https://vercel.com/dodo9944-ops-projects/seul21/settings/environment-variables
2. 각 변수 추가 (06_로그인정보_템플릿.md 참고)
3. "Save" 후 재배포

### 5-2. GitHub Secrets
1. https://github.com/dodo9944-ops/seul21/settings/secrets/actions
2. 각 Secret 추가
3. 이후 워크플로에서 자동 사용

### 5-3. 토큰 재발급 (유출 의심 시)
| 토큰 | 재발급 경로 |
|------|------------|
| GitHub PAT | GitHub Settings → Developer settings → Personal access tokens |
| Telegram Bot | @BotFather → /revoke → /newbot 또는 /token |
| Anthropic Key | https://console.anthropic.com → API Keys → Create |
| Google OAuth | Google Cloud Console → 사용자 인증 정보 |
| Vercel Token | Vercel Settings → Tokens |

## 6. 데이터 JSON 복원 (granular)

### 6-1. 특정 시점의 community.json만 복원
```bash
git log --all --oneline -- redevelopment/data/community.json
# 원하는 커밋 식별 후
git checkout <커밋SHA> -- redevelopment/data/community.json
git commit -m "restore community.json to <SHA>"
git push origin master
```

### 6-2. 구문 검증
```bash
node --check redevelopment/data/community.json  # 실패 시 JSON 오류
node -e "JSON.parse(require('fs').readFileSync('redevelopment/data/community.json','utf8'))"
```
