# 홈페이지 제작설명서 — 기술 스택 및 빌드 가이드

## 1. 기술 스택

| 레이어 | 기술 | 비고 |
|--------|------|------|
| 프론트엔드 | Vanilla HTML + CSS + JavaScript (ES6+) | 빌드 도구 없음 — 정적 파일 직접 배포 |
| 런타임 | 브라우저 (SPA 아님·페이지 단위 렌더) | |

| 아이콘 | Font Awesome 6.5.1 (CDN) | |
| 지도 | Leaflet 1.9.4 (OpenStreetMap) | `location.html` |
| 폰트 | Google Fonts — Noto Sans KR | |
| 서버리스 | Vercel Serverless Functions (Node.js) | `redevelopment/api/*.js` |
| 호스팅 | Vercel | `seul21.com` 도메인 |
| 저장소 | GitHub (`dodo9944-ops/seul21`) | |
| 데이터 저장 | JSON 파일 (GitHub 저장) + Supabase (일부) | GitHub Contents API로 읽고 쓰기 |
| 알림 | Telegram Bot API | 커뮤니티 글 작성·문의 알림 |
| 인증 | 자체 이메일/비밀번호 + Google OAuth | sessionStorage 기반 |
| AI | Anthropic Claude API | 챗봇 `chat.js`, `chat-law.js`, `chat-expert.js` |

## 3. 캐시버스팅 규칙

공유 JS/CSS/데이터 파일 수정 시 **반드시** 모든 HTML의 `?v=` 파라미터를 일괄 갱신.

대상:
- `common.js`, `common.css`
- `mock-data.js`, `areas-data.js`, `data-service.js`
- `chatbot.js` 등

검증 명령 (예시):
```bash
# 파라미터 누락 검사
grep -rE 'common\.js"' redevelopment --include='*.html' | head
# 구 버전 잔존 검사
grep -rE 'common\.js\?v=OLD_VERSION' redevelopment --include='*.html'
```

## 6. 배포 절차

```bash
# 1. 로컬 수정 후
git add <files>
git commit -m "설명"
git push origin master

# 2. Vercel이 자동으로 감지 → 빌드 → 배포
# 3. seul21.com에서 확인
# 4. 텔레그램으로 처리 결과 보고 (/api/report)
```

**⚠ CLAUDE.md 특별 규정**: 모든 작업 완료 후 텔레그램 보고 의무.

## 7. 로컬 개발 (선택)

정적 사이트이므로 간단한 HTTP 서버면 충분:
```bash
cd redevelopment
python3 -m http.server 8080
# http://localhost:8080
```

API 함수는 로컬에서는 동작하지 않음 → Vercel 프리뷰 배포로 검증.

## 9. 접근성 / 브라우저 정책

- **권장 브라우저**: 삼성 인터넷 (모바일), Edge/Whale/Firefox (데스크톱)
- **Chrome 언급 금지** (CLAUDE.md 규정, 2026-04-18~)
- 뷰포트: `width=device-width, initial-scale=1.0`
- 반응형 breakpoint: 768px (모바일), 1024px (태블릿)
