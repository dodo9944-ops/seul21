## 3. 장애 대응 플레이북

### 장애 A: 사이트 접속 불가
1. Vercel 상태 확인 → `https://vercel.com/dodo9944-ops-projects/seul21`
2. 최근 배포 실패 여부 → GitHub Actions 탭 확인
3. 도메인 DNS → 가비아(Gabia) 관리 페이지
4. 긴급 롤백: GitHub에서 직전 커밋으로 revert + push

### 장애 B: 자료실 항목 미노출
1. 카테고리 매핑 확인 (`catDefs.keys`, `_catKeyMap`)
2. fileMap 등록 여부 확인
3. 캐시버스팅 버전(`?v=`)이 전 HTML 동기화되었는지 Grep
4. 브라우저 캐시 강제새로고침

### 장애 C: "파일 준비 중" 토스트
1. `fileMap`에 해당 ID 등록 여부 확인
2. `downloads/` 폴더에 상세 HTML 존재 여부 확인
3. 외부 링크 `gov` 사용 금지 — `web` 또는 `ext`로 전환

### 장애 D: 텔레그램 알림 미수신
1. `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` Vercel 환경변수 확인
2. `/api/report` 수동 호출 테스트
3. 봇 → 채팅방 멤버십 유지 여부

### 장애 E: 커뮤니티 글 저장 실패
1. `GITHUB_TOKEN` 유효성 (만료 여부) 확인
2. GitHub API rate limit 확인 (authenticated 5000 req/h)
3. `community.json` 구문 오류 확인 (`node --check`)

### 장애 F: 데이터 손실 (최악 시나리오)
**즉시 사건 경위서 작성 + 롤백**

1. 가장 가까운 과거 커밋 식별
2. `git checkout -b restore-YYYYMMDD <commit>` — 복원용 브랜치
3. 필요 데이터만 선별 복원 (전체 롤백 금지 — 이후 작업 손실 방지)
4. `INCIDENT_REPORT_YYYYMMDD.md` 작성
5. CLAUDE.md 판단 실패 사례에 추가

## 4. 배포 절차

### 정상 배포
1. 수정 → `git add` → `git commit` → `git push origin master`
2. Vercel 자동 감지 → 빌드 (보통 1~2분)
3. https://seul21.com 에서 반영 확인
4. 미반영 시 GitHub API `push_files`로 강제 재커밋

### 프리뷰 배포 (PR)
1. feature 브랜치 → GitHub PR
2. Vercel이 PR별 프리뷰 URL 자동 생성
3. 댓글로 프리뷰 링크 게시
4. 사용자 검증 후 머지

### 캐시 무효화
- `vercel.json`에 HTML/JS/CSS `no-cache` 헤더 유지
- 여전히 캐시 잔존 시 → 파일 내용 자체 변경하여 재배포 강제

## 5. 백업 운영

### 자동 백업 (일요일 02:00 KST)
- `.github/workflows/backup-to-gdrive.yml` cron 실행
- ZIP 아티팩트 90일 + Google Drive 영구 + GitHub 브랜치 영구

### 수동 백업
```bash
git tag backup-$(date +%Y%m%d) HEAD
git push origin backup-$(date +%Y%m%d)
# GitHub Actions 페이지에서 Run workflow 클릭
```

### 복원
```bash
git fetch origin
git checkout -b restore-test backup-YYYYMMDD
# 검증 후 master로 반영 (사용자 명시 승인 필수)
```
